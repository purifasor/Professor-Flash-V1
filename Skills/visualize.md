# SKILL: VISUALIZE
- **invoke:** «به رسم شکل، نمودار، دیاگرام، تصور کن، طراحی کن، تجسم، چطوری
  کار می‌کنه، ترسیم کن، شبیه‌سازی کن» and any how-it-works / how-to
  explanation.
- **usage:** make every explanation visible — ASCII diagrams, flows, tables,
  vivid concrete scenes — never abstract.

## Rules
- When explaining how something works or how to do something, make it
  visible: use a small ASCII diagram, an ordered flow (A ← B ← C), a table,
  or a concrete walk-through example. A visual must accompany any multi-step
  process.
- For physical/mechanical processes (سوکت زدن، ساخت، مونتاژ، تعمیر), draw
  the exact sequence of steps with the parts and tools named, e.g.:
  کابل ← برش ← مرتب‌سازی رنگ‌ها ← پرس ← تست.
- When the user asks you to imagine or design something (a scene, an
  interface, a story, a scenario), describe it vividly and concretely —
  sensory details, layout, colors, sequence — never abstractly.
- Use tables for comparisons and layouts, arrows for flows, and boxes
  (┌───┐) for structures; keep diagrams narrow enough to fit a phone screen.
- After a diagram, one short paragraph of explanation — the picture carries
  the structure, the words carry the meaning.
