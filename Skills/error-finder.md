# SKILL: ERROR FINDER (شناسایی و رفع هر خطا)
- **invoke:** «خطا، ارور، error، exception، stack trace، کد خطا، DLL، بایوس،
  crash، کرش، هنگ، خراب شد، کار نمی‌کنه، پاپ‌آپ، نصب نشد، اجرا نشد» + هر
  متنی که کاربر داخل «
  » یا بین علامت‌های کد فرستاده و شبیه پیام خطاست.
- **usage:** تشخیص سیستماتیک: اول بفهم خطا چیست (دسته‌بندی)، بعد علت، بعد
  راه‌حل قدم‌به‌قدم، بعد پیشگیری — به هر زبانی که پیام خطا نوشته شده باشد.

## گام‌های تشخیص (همیشه به همین ترتیب)
1. **متن خطا را کامل بخوان:** پیام دقیق، کد خطا (عدد/hex)، نام فایل/خط، و
   متغیرهای همراه را جدا کن. هیچ قسمتی از متن خطا را نادیده نگیر.
2. **دسته‌بندی کن:** خطا از کدام خانواده است؟
   - کد/زبان برنامه‌نویسی (پایتون، JS، C/C++، C#، Java، PHP، Go...)
   - سیستمی/ویندوز (کدهای 0x، Event Viewer، BSOD)
   - DLL/اجرایی (فایل گمشده، نسخهٔ ناسازگار، ثبت DLL)
   - مسیر (path) — مسیر پیدا نشد، متغیر PATH، فاصله/حروف خاص در مسیر
   - بایوس/سخت‌افزار (بوق‌ها، کدهای POST، تنظیمات)
   - تاریخ/ساعت (همگام‌سازی، باتری بایوس، timezone)
   - شبکه (اتصال، DNS، پروکسی، تایم‌اوت)
   - زبان/لوکال (خطا به روسی، چینی، عربی یا هر زبان دیگر)
3. **علت‌های محتمل را رتبه‌بندی کن:** از محتمل‌ترین و کم‌خطرترین شروع کن.
4. **رفع قدم‌به‌قدم:** هر مرحله را جدا بنویس با کاری که کاربر باید انجام دهد و
   چطور نتیجه را چک کند؛ اگر مرحله جواب نداد، مرحلهٔ بعدی.
5. **پیشگیری:** یک خط کوتاه که چطور از تکرار خطا جلوگیری شود.

## راهنمای دسته‌بندی‌ها
- **خطاهای کد:** به stack trace نگاه کن — اولین خطِ «خطای خودت» (نه کتابخانه)
  معمولاً محل مشکل است. خطاهای رایج هر زبان را بشناس:
  پایتون (SyntaxError، NameError، TypeError، ImportError، IndexError،
  FileNotFoundError)، JS (ReferenceError، TypeError، Cannot read property)،
  C/C++ (segmentation fault، linker error، undefined reference)،
  C# (NullReferenceException، FileNotFoundException)، Java (NullPointerException،
  ClassNotFoundException، OutOfMemoryError)، PHP (parse error، Fatal error).
- **DLL/اجرایی:** «DLL not found» یعنی فایل گمشده یا نسخهٔ ناسازگار — چک
  رجیستری/ثبت DLL، نسخهٔ Visual C++ Redistributable، و دایرکتوری اجرایی؛
  «is not a valid Win32 application» یعنی معماری (32/64) یا فایل خراب.
- **مسیر:** path too long، فاصله در مسیر بدون کوتیشن، حروف فارسی/فضا در PATH،
  مسیرهای نسبی در برابر مطلق، جداکننده‌های / و \.
- **بایوس:** توالی بوق‌ها را با راهنمای سازنده مقایسه کن (1 کوتاه = خوب،
  بوق‌های تکرارشونده = حافظه/گرافیک/مادربرد)؛ کدهای POST را از دفترچه بخوان.
- **تاریخ/ساعت:** خطاهای گواهی SSL/TLS، خطاهای همگام‌سازی، گاهی ناشی از
  تاریخ/ساعت اشتباه سیستم است — چک کنید با سرور زمان همگام است.
- **زبان‌های دیگر:** کلیدواژه‌های رایج را بشناس و ترجمه کن:
  روسی (ошибка = خطا، не найден = پیدا نشد، не удалось = ناموفق، доступ
  запрещён = دسترسی ممنوع)، چینی (错误 = خطا، 找不到 = پیدا نشد، 无法 =
  نمی‌تواند)، عربی (خطأ، غير موجود، رفض الوصول) — به معنی خطا برس، نه به ظاهر.

## قالب پاسخ حرفه‌ای
- «**خطا:** <پیام دقیق و کامل>»
- «**نوع:** <دسته>»
- «**علت:** <۲-۳ علت محتمل به ترتیب>»
- «**رفع:** قدم‌به‌قدم شماره‌دار — هر قدم: کاری که باید بکنی + چگونه چک کنی»
- «**پیشگیری:** یک خط»
- اگر خطا ناشناخته بود: بگو کدام اطلاعات کم است (سیستم‌عامل، نسخه، متن کامل
  خطا) و محتمل‌ترین مسیرهای رفع را بده.
